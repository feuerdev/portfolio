# Working on feuer.dev

Static HTML, CSS and TypeScript, deployed through GitHub Pages. One document has
two presentations: plain HTML by default, and an optional animated fancy mode.
Keep the default fast and readable without JavaScript. Preserve all five policy URLs.

## Local commands

Use `.nvmrc`: Node 24.15.0, tested with npm 11.12.1. Retain npm's committed lockfile.

```sh
nvm use
npm ci
npm run dev
```

Preview at `http://127.0.0.1:5000`. Use `PORT=5001 npm run dev` if occupied.
Run `npm run watch` in a second terminal while editing TypeScript, then refresh.
These commands use a POSIX shell. No Docker, credentials or global compiler needed.

Before handing off a change: `npm run build`, `npm test`, `git diff --check`.
For dependency changes, verify a fresh `npm ci` and review `npm audit`.

## Structure

- `public/index.html`: the shared content, external links, project descriptions and metadata.
- `public/css/style.css`: plain-mode rules, hidden decorative/accessibility elements and the mode switch.
- `public/css/fancy.css`: optional presentation, loaded on demand. Scope rules to `.fancy`.
- `src/app.ts`: in-memory mode switching, lazy loading, legacy mode-query cleanup and the optional View Transition.
- `src/analytics.ts`: production homepage analytics, privacy preferences and payload sanitization.
- `src/frontend-teaser.ts`: the inline rift on "frontend" in plain mode.
- `src/page-reveal.ts`: the mobile circular reveal, independent of native viewport capture.
- `src/particle-palette.ts`: the shared universe and teaser colours.
- `src/fancy.ts`: fancy-mode lifecycle, scroll zoom/orbit, rotation, pointer and motion controls.
- `src/space.ts`: the particle scene: sun, stream, project knots, stars and camera.
- `public/js/*.js`: generated by TypeScript. Never edit or commit these files.
- `public/assets/`: local images and the locally hosted IBM Plex Sans with its licence.
- `public/css/policy.css`: shared presentation for the four app policy/terms pages.
- `tests/`: static hosting paths, policy URLs, progressive enhancement and analytics.

## Modes

Every load and refresh starts plain. The switch keeps the presentation in memory,
never in the URL, cookies or storage. Remove a legacy `mode` query parameter
without losing other parameters or fragments. Switching keeps content, keyboard
focus and reading position usable, and focus moves to the newly available mode
control.

Plain mode uses browser-default layout, fonts, spacing and colours in light mode.
Do not centre it, constrain its width or introduce a visual theme. It loads no
external fonts or decorative images. The one exception is the rift on the final
word "frontend" in the first introductory sentence, which is the entry to fancy
mode. Without JavaScript it is ordinary text, and in fancy mode it becomes
ordinary text while "Back to plain HTML" and a pause button appear top right on
desktop and bottom right on mobile.

The rift is a torn, breathing black opening with an amber rim and a slowly
swirling starfield inside it. Nothing is drawn outside the opening. Difference
blending turns the word white; keep the edge crisp so text crossing it stays
legible. A fine mouse nearby grows and stretches the opening and shifts the stars
slightly; a stationary pointer adds no motion. Activation swirls the stars into
the centre, then starts the reveal from the word. The teaser loads nothing from
fancy mode, caps its backing resolution at 1.5x, avoids layout reads per frame
and stays within the viewport. It stops in fancy mode, offscreen, on hidden tabs
and under reduced motion, which keeps a still drawing.

The reveal is an 850ms circular wipe. Load both font weights before capture,
fall back to sans-serif on font failure, and start the universe's formation when
the new view is ready so it forms during the wipe. Desktop uses a CSS keyframe on
the native new-view pseudo-element with coordinates set once per switch. Narrow
screens and coarse pointers use `src/page-reveal.ts`, an inert Shadow DOM copy of
the old view with an expanding radial-gradient mask. Native capture was cancelled
on Android when the viewport changed, and a clip-path wipe did not render on a
Pixel, so keep the mask approach. Freeze the copy's colours, root-relative sizes
and canvas frame, animate only its mask, and remove it after the animation,
including on failure. Reuse loaded CSS and keep one live universe renderer. `data-reveal-result` and
`data-reveal-reason` record the browser's outcome; do not label a skipped
transition as successful. Log transition failures. Failed fancy downloads offer
an explicit page reload because browsers retain failed module imports.

## Fancy mode

Always dark: IBM Plex Sans, blue links and amber accents over a fixed canvas with
a glowing sun and a particle stream, where each project is a knot. Always show
content while fancy assets load, and keep it readable if decorative loading or
browser features fail. Do not add animation dependencies for effects native
browser APIs can handle. See `docs/fancy-design-review.md` for the design.

Scrolling performs one zoom and sideways camera orbit, placing the sun beside the
cards by the first card, and reverses when returning to the introduction. The
stream always rotates slowly and scrolling adds rotation and slight angle drift.
Keep the opening's formation, drift and name splitting. On narrow screens crop a
dimmer sun at the right edge instead of narrowing the cards. A sparse, dim sky
surrounds the stream without glow sprites, twinkle or wake physics.

Pause freezes rotation, drift, twinkling and the pointer wake, but the zoom still
follows reading position. Hidden tabs and leaving fancy mode stop rendering.
Reduced motion keeps a static overview. Fine, hover-capable mice tilt the camera
and sweep a dust wake that changes nearby particles' orbital speed and spacing;
stationary pointers exert no force. No particle-to-particle physics. Touch-only devices skip the wake entirely,
and connecting or removing a mouse enables or clears it. Keep the 1.5x backing
resolution cap.

The canvas uses `100lvh` with a `100vh` fallback so mobile toolbars do not
reframe it. Active animation reads the native scroll position before drawing each
frame, and the title's paused animations are scrubbed in the same loop. Do not
update inherited root styles while scrolling. Desktop Safari (not mobile Safari or
iPads) smooths visual scroll steps with time-based damping; native scrolling stays
untouched and passive.

Projects are glass cards with the text above the artwork. Keep text at WCAG AAA
contrast and give text outside cards a dark halo. Particles use additive blending
in pre-sorted batches, scale with the viewport, and are hidden behind the sun
including their glow.

## Content

Keep the document semantic: native links and buttons, visible keyboard focus and
a skip link. Neither mode has section navigation. Mode switches and direct
project links position immediately. Preserve native hashes, history and focus.

Keep copy factual and concise. The introduction is the name, about text, AI
sentence and contact links, with no masthead, role eyebrow or repeated about or
contact sections. Each project is a linked heading (inline in plain mode) and one
short paragraph, visible in both modes, with no expandables, technology tag lines,
decorative link arrows or generic "Read the source" links. Native horizontal rules
separate the plain document's intro, projects and footer.

Project order is keep-mcp, human-api, llm-autobattler, split-keyboards,
yt-sponsor-detect, heron-deterrent, agent-box, feuer-io, swift-raytracer and
big-pond. Each project's heading, anchor and analytics event use one lowercase
slug; where the product name differs, the paragraph names it. Keep Vorsorge off
the page for now. The keep-mcp popularity claim refers to GitHub stars; recheck it
when updating copy.

Use authentic captures for project artwork (see `docs/content-sources.md`). Keep
media areas consistent and bounded, preserve aspect ratios and do not enlarge the
old raytracer capture. Images load only in fancy mode; plain mode links to the
Scylla photos without loading them. Keep WebP exports small and free of metadata.
The heron-deterrent clip is the one moving artwork: a muted looping video with
`preload="none"` and a poster that plays only while fancy motion runs.

Update the footer's "Last updated" date and its `<time datetime>` when content changes.

## Analytics

Keep resources local except the asynchronous GoatCounter tracker at
`https://gc.zgo.at/count.js`, loaded only on the HTTPS homepage at `feuer.dev`
(including `/index.html`) after checking Do Not Track and Global Privacy Control,
and checked again before each count. The CSP permits only that tracker and
`https://feuerdev.goatcounter.com/count`. Keep inline script and style blocked.

Disable the automatic pageview and sanitize `get_data` before the first count:
`/` for the homepage, no separate query field, referrers reduced to HTTP(S)
origins. Event paths and titles are fixed HTML attributes. Count each project's
links as one event, the four introduction links separately, and completed mode
changes as `mode-fancy` or `mode-plain`, never as another pageview. Keep both
modes combined under GoatCounter's session deduplication. Preserve native
click and middle-click behaviour and ignore right-clicks. Analytics failures and
early clicks must not block navigation or switching. The app dispatches a
`portfolio-mode-change` event with the target mode as a boolean and never imports
the analytics module. No queued events, noscript pixel,
collector proxy or persisted visitors. Retain aggregate statistics for 24 months.
See `docs/analytics.md` for the account
settings, and keep the privacy notice aligned with them.

## Verification and publishing

Use a `feat/`, `fix/` or `chore/` branch from `master` and preserve unrelated
changes. Merging and production deployment require user authorization.

Automated tests cover critical paths only: static hosting paths, policy URLs, the
document without JavaScript and analytics privacy. Everything else is verified by
looking at the running page. No test drives the browser.

When Jannik wants quick iterations, such as brainstorming, trying ideas or
prototyping, iterate without running checks or taking screenshots; he looks at the
running page. Say in one line when you start and when you stop exploring. Exploring
ends when he wants to keep the result, at the latest when a PR is being prepared.

Before a PR, run `npm run build`, `npm test` and `git diff --check`, and look once at
plain and fancy mode on desktop and a narrow mobile width.

Pushes to `master` publish `public/` through `.github/workflows/pages.yml`; PRs
only build and check. Keep actions pinned and deployment permissions restricted.
Internal links must work at the domain root and under `/portfolio/`. Roll back by
reverting and redeploying `master`.

`public/impressum.html` holds the provider details in German with a c/o address
from the Online-Impressum address service. Keep its wording verbatim and never
replace the address. The website privacy policy describes the static site and
GitHub Pages hosting. App policy pages are separate and keep their legal wording.
See `docs/publication-notes.md` for legal sources.

Update this file when commands or behaviour change, and the README when commands
change. Private server operations belong in `feuerdev/setup`. Never commit secrets.
